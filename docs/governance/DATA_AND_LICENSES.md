# Data rights, intellectual property, licensing and content policy

This repository being public does not make its original code open-source. **No top-level LICENSE has been selected yet**. Contributors must request maintainer guidance before assuming reuse, redistribution or commercial rights. This document is not legal advice.

## Problem statements, tests and editorial content

- Prefer original author-written problems with explicit contributor permission and review.
- Consider partner/educator-licensed problems with recorded agreements.
- Where sourcing publicly available material, independently confirm reproduction and commercial-use rights (including images, tests, statements, solution explanations).
- Never assume Codeforces/LeetCode/AtCoder/ICPC public accessibility grants unrestricted copying.
- Keep provenance: title, original author, source URL, license or written permission, version, date and permitted uses.
- Do not collect private hidden tests or bypass access controls.
- Provide removal/correction process for rights concerns.

## AI datasets and training

Track permissions for training, redistribution and commercial usage separately. Scraped competitive-programming solutions may contain third-party copyright. Honor platform terms and original author rights. Do not use noncommercial educational material as if commercially licensed. Do not mix evaluation problems with training sets.

## Open-source dependencies

Maintain component inventory with version/commit, URL, license, copyright notices, obligation checklist and any source-distribution requirements. Review MIT, Apache, GPL/AGPL, model licenses, optional enterprise features and transitive libraries; do not assume 'GitHub public' means 'free to copy'.

## Product ownership

Owner controls original application source, project direction, branding and deployment. Third-party code and model weights remain governed by their respective licenses. Obtain permission/assignment/contributor licensing policy consistent with the project's chosen outbound license.

## User privacy and security

Define consent, deletion, data retention, usage of user submissions for model training, and third-party model disclosure before collecting production user data. Never silently train on private submissions. Store credentials outside Git.

## Before public launch

Maintainer chooses license and contributor policy, records rights to seed problems/test cases, obtains security review of execution engine, publishes user privacy/terms and addresses potential trademark confusion.
